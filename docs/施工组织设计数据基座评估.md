# 施工组织设计数据基座评估

> 问题：现有数据能支撑什么样的施组？要做"非常专业且中标率高"的施组，还缺什么？
> 方法：以 GB/T 50502-2009 第 3.0.4 条的八段式结构为骨架，逐段对照现有数据；再从施组评分机制反推"什么数据真正影响中标率"。

---

## 一、先看评分机制：施组是怎么被打分的

调研了多份真实评标记录，施组评分有三个特点：

**① 细到 0.1 分，项数多**

某评标委员的施组评分表实测分值：

```
关键施工技术、工艺及重点难点和解决方案   1.91 / 1.85 / 1.62 / 1.72
施工进度计划和各阶段进度的保证措施       0.87 / 0.90 / 0.87 / 0.85 / 0.80
```

每项 1-2 分，一份施组通常 15-30 个评分点。

**② 去掉最高最低分取平均**

> "施工组织设计各评分点得分应当取所有技术标评委评分中分别去掉一个最高和最低评分后的平均值为最终得分"

意味着**不能靠一个评委打高分取胜**，必须每项都稳住。

**③ 评分标准是"分级描述"式**

南京某项目实测：

```
施工方案和技术措施（0~8.00）
  1.1 内容完整、总体方案合理可行、技术措施有针对性得 2 分
  1.2 ……（逐条扣分，最多扣 20 分）
```

**结论：施组不是"写得好"能赢，是"每一项都比对手好一点点"才能赢。** 20-30 项 × 每项差 0.1-0.3 分，累积起来就是 3-9 分的差距——而技术标总分可能只有 20-30 分。

## 二、现在有什么：八段式逐段对照

GB/T 50502-2009 第 3.0.4 条规定的施组内容：

> 编制依据、工程概况、施工部署、施工进度计划、施工准备与资源配置计划、主要施工方法、施工现场平面布置、主要施工管理计划

| # | 章节 | 现有数据 | 覆盖度 | 能写出什么 |
|---|---|---|---|---|
| 1 | **编制依据** | 505 条标准（99.8% 验证）+ DB34 5,651 条 + 10 条法规 | **✅ 完整** | 可直接出稿，按项目类型自动匹配，含全文强制规范 |
| 2 | **工程概况** | 公告正文含「建筑面积」1,175/8,188（14%）、「结构类型」41（0.5%）、「层数」3、「计划工期」271（3.3%） | **❌ 严重缺** | 只能写项目名称和招标范围，写不出"这是什么工程" |
| 3 | **施工部署** | 无 | **❌ 缺** | 组织架构、区段划分、施工顺序全无依据 |
| 4 | **施工进度计划** | 890 条合同工期（均值 296 天）、1,698 份招标文件有工期候选 | **⚠️ 部分** | 能说"同类项目平均 296 天"，但写不出工序逻辑和横道图 |
| 5 | **施工准备与资源配置** | 无（消耗量定额未入库） | **❌ 缺** | 人材机数量只能拍脑袋 |
| 6 | **主要施工方法** | 146 条施工验收规范（管"验收什么"，不管"怎么做"） | **⚠️ 部分** | 能说"按 GB 50204 验收"，写不出工艺步骤 |
| 7 | **施工现场平面布置** | 无 | **❌ 缺** | 塔吊位置、加工区、临时道路全无依据 |
| 8 | **主要施工管理计划** | 规范中有质量/安全/环保要求；11,831 条评分类条目知道评委考什么 | **⚠️ 部分** | 能写出"符合规范"的通用条款，写不出针对性措施 |

**八段里：1 段完整、3 段部分覆盖、4 段基本空白。**

## 三、缺口深挖：缺的到底是什么

### 缺口 1：工程概况（最致命，也最容易补）

**为什么致命**：施组的所有"针对性"都从这里出发。不知道建筑面积、结构类型、层数、跨度，就写不出：

- 施工部署（几个区段？竖向怎么划分？）
- 主要施工方法（现浇还是装配？大跨度还是常规？）
- 资源配置（多少工日？什么机械？）
- 重难点（深基坑？高支模？大跨度吊装？）

**为什么容易补**：**数据就在本地 1,982 份招标文件 PDF 里**，在"投标人须知前附表"章节。之前为了提取评标办法解析过这些 PDF，但只抽了评标相关的表，没抽工程概况。

需要抽的字段：

```
建筑面积 / 占地面积 / 建筑层数（地上/地下）/ 檐高 / 结构类型
基础形式 / 最大跨度 / 抗震设防烈度 / 计划工期 / 质量标准
招标范围 / 暂列金额 / 专业分包内容
```

**成本**：1,982 份 × 约 5 秒 = 3 小时（复用现有 `extract_tender.py` 框架，加一个 section 提取函数）

---

### 缺口 2：工期定额与工序逻辑（进度计划的根）

**现状**：只有"结果数据"（890 条合同工期），没有"依据数据"（为什么是这个工期）。

**缺什么**：

| 需要 | 用途 | 数据源 | 可得性 |
|---|---|---|---|
| 工期定额 | 给定面积/结构/层数 → 算合理工期 | 各省住建厅发布 | **公开，可下载** |
| 工序逻辑 | 基础→主体→装修的前后关系与搭接 | 行业通用知识 + 工法 | 可结构化 |
| 类似项目实际工期 | 校验定额算出的工期是否合理 | 已有 890 条 | 已有 |

**关键判断**：如果只能给出"同类项目平均 296 天"，这是**统计描述**；如果能给出"3 层框架结构、2,000㎡ 的常规工期应为 180-220 天，本项要求 240 天属宽松"，这是**专业判断**。后者才拿分。

---

### 缺口 3：消耗量定额（资源配置的根）

**现状**：完全空白。资源配置只能写"配备充足的人材机"——这是典型的不得分表述。

**缺什么**：《房屋建筑与装饰工程消耗量定额》TY01-31-2015（全国通用）、安徽省概算定额 2025 版。

**能支撑什么**：

```
已知：建筑面积 20,000㎡ 框架结构、工期 300 天
查定额：每 100㎡ 建筑面积约需 X 工日、Y 吨钢材、Z m³ 混凝土
推算：总工日 → 平均劳动力 → 高峰期劳动力 → 生活区规模 → 平面布置参数
```

**这是一条链**：定额 → 资源量 → 劳动力曲线 → 平面布置。没有定额，后面全断。

**可得性**：公开，省住建厅有 PDF。

---

### 缺口 4：施工工法（施工方法的根）

**现状**：146 条施工验收规范管的是"验收标准"，不是"怎么做"。

**缺什么**：工法库。住建部每两年评一批国家级工法（2007-2008 年 417 项、2013-2014 年 404 项），各省也有省级工法（江苏一年 1,359 项）。

**关键限制**：**工法名称公开，工法正文通常不公开**。

所以能拿到的是"有哪些先进工艺"，拿不到"工艺怎么做"。写施组时，"采用 XX 工法"这句话能写，"具体操作要点"写不出。

**价值判断：中等偏低。** 除非能拿到工法正文（专利/期刊/企业公开资料），否则只是名词库。

---

### 缺口 5：重难点问题库（真正拉开差距的地方）

**为什么关键**：评委看施组，最先看的就是"你知不知道这个项目的难点在哪"。

某评标表实测分值：**"关键施工技术、工艺及工程项目实施的重点、难点和解决方案" 1.62-1.91 分**——是施组里单项分值最高的。

**缺什么**：类似项目**实际遇到过什么问题**。

**潜在数据源（现有数据里就藏着）**：

| 数据源 | 现存量 | 能挖出什么 |
|---|---|---|
| 变更公告 | 有（nature 分类里） | 哪类项目变更最多、变更什么 |
| 答疑澄清文件 | 附件里有 | 投标人问什么 → 说明哪里有歧义/风险 |
| 废标/流标公告 | 有 | 什么原因导致失败 |
| 履约超期记录 | 154 条超期 | 哪类项目容易拖期 |

**这是被忽略的金矿**：答疑澄清文件是"投标人集体提问"，直接暴露项目的真实难点。比如"基坑周边有既有建筑如何处理"，那就是这个项目的难点。

---

### 缺口 6：平面布置（最难，也最不影响得分）

**现状**：空白。

**为什么难**：需要图（不是文字），且强依赖场地条件（红线形状、周边道路、水电接入点）。

**为什么可能不重要**：多数施组评分里，平面布置分值占比不高（通常 1-2 分），且评委难以在几分钟内判断"这个布置好不好"。

**结论：优先级最低。** 除非目标是拿满分，否则用通用模板 + 关键参数（塔吊覆盖半径、加工区面积）即可。

## 四、一个更根本的判断：AI 写施组的天花板在哪

把施组内容按"能否靠数据生成"分三类：

| 类型 | 特征 | 占篇幅 | 占分值 | AI 能做什么 |
|---|---|---|---|---|
| **通用模板段** | 质量体系、安全制度、环保措施 | 50-60% | 20-30% | **能写到比人好**——语言规范、逻辑严密、无遗漏 |
| **参数推导段** | 工期计划、资源配置、劳动力曲线 | 20-30% | 30-40% | **有定额就能算准**，没定额就是空话 |
| **项目特定段** | 重难点分析、针对性方案、部署策略 | 20-30% | **40-50%** | **这是天花板所在**——需要本项目信息 + 类似项目经验 |

**关键洞察**：

AI 在通用模板段已经超过大多数人（人写得啰嗦、有遗漏），但**这部分恰恰是评委扫一眼就过的**——因为所有投标人都写得差不多。

真正决定成败的是第三类。而第三类需要的是：

```
本项目的具体条件（工程概况）  +  类似项目的真实经验（重难点库）
```

**这两样恰好都是现在的缺口。**

## 五、补数据的优先级（按 ROI 排序）

### 实测结论：工程概况的四个误区与一个真相

跑了三轮验证，先否定了四条路，最终找到了真相但仍不可用：

| 路径 | 实测 | 结论 |
|---|---|---|
| ① 投标人须知前附表 | 平均 1.4 字段/份，只有「质量标准」「招标范围」 | ❌ |
| ② 招标计划（423 份 PDF） | 平均 0.5 字段/份 | ❌ |
| ③ 工程量清单章节 | 章节仅 1-2 页（索引页） | ❌ |
| ④ 评分细则反推特征 | 仅 87/1965 份（4.4%） | ❌ |
| **⑤ 造价成果文件压缩包** | **内容确实有，但覆盖率 0.8%** | **⚠ 找到但太少** |

**真相：工程概况在「造价成果文件」的「工程量清单总说明.doc」里。**

实测金寨一中项目解压后的完整内容：

```
一、工程概况
本项目建筑面积 11800 平方米，地上建筑面积 11800 平方米（地上三层）。

五、其他需要说明的问题
1、暂列金额 1,360,000.00 元
4、本项目脚手架采用【盘扣式脚手架】
5、本项目智慧工地等级为基本级（7 项控制要求）
7、干混砂浆、商品混凝土、水泥稳定级配碎石按暂定主材价计入
```

**这才是施组真正需要的：面积、层数、脚手架形式、智慧工地等级——每一条都能直接写进施工部署。**

**但覆盖率是硬伤**（扫描 514 个 zip）：

```
清单总说明      4 / 514   0.8%
Excel 清单    24 / 514   4.7%
限价编制说明   16 / 514   3.1%
图纸          18 / 514   3.5%
广联达计价文件   12 / 514   2.3%
```

**结论：不是技术上拿不到，是站点本身不发布造价成果文件。** 要规模化必须换数据源（施工图审查系统、造价咨询机构公开数据、或直接向招标代理索取）。

### 两个 P0 的实际情况

**P0-1 工程概况——内容找到了，但覆盖率不够**

`sections_json` 里确实存了章节页码：

```json
{"招标公告":{"pages":[2,3,4,5,...],"count":9},
 "投标人须知":{"pages":[2,4,6,9,12,18,...],"count":32},

```

**「投标人须知」章节已定位（32 页）**——但实测这里只有「质量标准」「招标范围」，拿不到面积和结构。

真正的内容在「造价成果文件」压缩包里（见上节），但覆盖率仅 0.8%。

**P0-2 重难点素材——比预期多得多**

| 素材 | 数量 | 能挖出什么 |
|---|---|---|
| **招标澄清文件（电子签章版）** | **557 个** | 投标人集体提的问题 → 直接暴露项目真实难点 |
| 答疑/澄清/补疑/变更 附件合计 | 330 个 | 同上 |
| 变更类公告 | 174 个 | 哪类项目变更频繁、变更什么 |
| 履约超期记录 | 154 条 | 哪类项目容易拖期 |
| 流标/废标公告 | 4 个 | 样本太少，参考价值低 |

**557 份招标澄清文件是最大的金矿**——它是「所有投标人提问 + 招标人答复」的集合，等于把项目的坑提前标出来了。

### 顺带发现：几个被完全忽略的附件类型

盘点附件名 Top 20 时发现：

| 附件名 | 数量 | 为什么有价值 |
|---|---|---|
| 招标计划.pdf | 277 | 通常含项目概况、投资估算、招标范围，**比招标公告更结构化** |
| 计划书.pdf | 56 | 同上 |
| 任务书.pdf | 55 | 设计/施工任务目标，重难点线索 |
| 政府采购意向.pdf | 46 | 采购需求与预算 |
| 履约保函.pdf | 70 | 实际履约金额与期限 |
| 中标通知书.pdf | 133 | 中标价与工期的官方确认 |

**这批附件从未被解析过**，但它们是补齐「工程概况」的另一条路——尤其「招标计划」可能比「投标人须知前附表」更好抽。

### 优先级表（修订版）

| 优先级 | 数据 | 状态 | 实际结果 |
|---|---|---|---|
| **已完成** | 重难点库（澄清问答） | ✅ | **6,544 条问答 / 462 个公告 / 432 条涉评分标准** |
| **已完成** | 造价档位画像 | ✅ | 1,181 条配对，工期随造价递升，下浮率在 1000-5000 万最高 |
| **已否决** | 工程概况字段抽取 | ❌ | 四条路全失败，真实位置覆盖率 0.8% |
| **已否决** | 消耗量定额 | ❌ | 无免费公开版 + **没有工程量数据，定额用不上** |
| 待定 | 换数据源取造价文件 | — | 需施工图审查/造价咨询渠道 |
| 待定 | 工法目录 | — | 只有名称无正文，价值中低 |
| 待定 | 平面布置图库 | — | 无公开渠道 |

### 关于消耗量定额为何不做

定额的用途是 **工程量 × 消耗量 = 资源量**。这条链的输入是工程量。

而工程量数据：
- 招标文件正文里的「工程量清单」章节只有 1-2 页（索引页）
- 真清单在 .rar/.zip 里，且 543 个压缩包只有 24 个含 Excel 清单（4.7%）
- 24 个样本无法泛化出资源配置算法

**即使拿到官方定额，也用不上。**

替代方案：用「造价 + 工期」档位 + 行业经验占比（人工 15-20%、材料 50-60%、机械 5-8%）估算，不追求定额级精度。

## 六、结论

**现在拥有的是一个"项目外部视角"的数据底座**：

```
评委怎么打分（12.7 万行评分表）
别人报了多少钱（3,430 条中标价 + 1,282 条限价）
该引哪些规范（505 条标准 + 5,651 条地标）
```

**缺的是一个"项目内部视角"的数据底座**：

```
这个工程是什么（工程概况）
这类工程怎么做（定额 + 工法）
这类工程容易出什么问题（重难点库）
```

**两个视角的差别**：

- 外部视角能回答"怎么写才能得分"→ 写作策略
- 内部视角能回答"这个工程该怎么施工"→ 技术实质

**施组评审的本质是后者。** 评委是工程专家，他们一眼能看出"这段是模板还是真懂"。

**最高性价比的两件事**（总计约 6-7 小时，均已验证可行）：

1. **从本地 1,982 份 PDF 抽工程概况**——`sections_json` 已定位「投标人须知」章节，只差一个提取函数
2. **挖 557 份招标澄清文件**——投标人问什么，就是项目的坑在哪

这两件做完，施组从"能写"变成"写得有针对性"。剩下的定额、工法都是锦上添花。

**另外一个意外发现**：277 份「招标计划」、55 份「任务书」、46 份「政府采购意向」从未被解析过，它们可能比「投标人须知前附表」更容易抽工程概况——值得先抽 20 份对比一下哪条路更好走。
