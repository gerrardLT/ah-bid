# 数据口径与已知问题

> 这份文档记录「哪些数字是可信的、哪些是已知缺口、哪些是刻意不修的」。
> 改动任何抽取器或分类器之前先读它，否则会重蹈覆辙。

最后更新：2026-11-04

---

## 一、三套口径（不能混）

### 1. 价格口径（`src/lib/price-stats.ts`）

| 口径 | 来源 | 覆盖 | 用途 |
|---|---|---|---|
| `limit` 限价 | `tender_control_price.price_kind='限价'` | 1,252 个招标公告 | 报价参考的基准 |
| `estimate` 估算 | 同上，`='估算'` | 494 个 | 无限价时回退，页面必须标「非投标上限」 |
| `mixed` 混 | 限价 + 估算 + 预算 | — | 只用于宏观对比，**不做建议报价** |

**单项目取价只允许走 `projectPrice(db, guid)`**。它在 `price-ref.ts` / 项目页三处替代了原来的 `MAX(amount)` —— 那个写法会把估算价当投标上限，让建议报价系统性偏高（494 个项目受影响）。

### 2. 分类口径（两套，刻意不合并）

| 用途 | 函数 | 类数 | 说明 |
|---|---|---|---|
| 报价线 | `typeOfTitle()` | 9（含「其他」1,421） | **冻结**。有 6 个消费者，改词会让 410 个价格配对重新分类 |
| 竞争地图 | `segmentOfTitle()` | 同上，但「其他」再细分到 1,058 | 构造性保证：`typeOfTitle !== '其他' ? 直接继承 : 只在其他里细分` |

**禁止改 `TYPE_KW`**。实测把「改造」加进房建会让 28 条配对从其他进房建（168→196），房建中位从 18.7% 漂移；而四道质量闸门**没有一条检查分类分布** —— 改坏了发现不了。

想扩分类就改 `src/lib/market-segment.ts` 的 `SEGMENT_RULES`（只收 ≥3 字复合词，禁止「改造/中心/基地」裸词）。

### 3. 业绩口径（三态，不是二分）

`announcement_perf.notice`：

| 值 | 含义 | 条数 |
|---|---|---|
| `'无门槛'` | 原文明确写「业绩要求：/」或「不要求」 | 3,318 |
| `'见招标文件'` | 只写「详见前附表」 | 2（见缺口 3） |
| `NULL` + `reason IS NULL` | 有实质门槛 | 3,108 |
| `NULL` + `reason` 非空 | 没抽到（正文没提业绩句） | 2,066 |

**「无门槛」是有效信息，不是「没抽到」**。项目页必须显示「本项目不设业绩门槛」，不能显示「未注明」。

## 二、已知数据缺口（不是 bug，是采集层的现实）

### 1. 合肥 395 条中标公告的正文是招标公告

```
标题: 2026年度长丰县教育系统建设项目...中标候选人公示
正文: 2026年度长丰县教育系统建设项目招标公告 1.招标条件...
```

**根因**：`origin_url` 里的 `infoid` 指向的是**招标公告**。实测调
`pageredirectnew` 接口，不管传 `categorynum=002002004`（中标结果）还是其他，
返回的都是 `/jyxx/002001/002001001/`（招标公告分类）—— **infoid 本身就错了**。

这是 `crawl.ts` 在列表页解析时的记录错误，不是抽取器问题。
修它要动 crawl 的列表解析，影响所有城市 → **未修，记录在案**。

**影响**：合肥 405 条中标公告只有 10 条有 winner（2.5%，其他城市 90%+）。
竞争矩阵里合肥那行标 ⚠。

### 2. 阜阳 / 滁州 / 淮南 / 安庆 / 六安：有中标结果，零限价

| 城市 | 中标结果 | 限价 |
|---|---|---|
| 阜阳 | 485 | **0** |
| 滁州 | 411 | **0** |
| 淮南 | 277 | **0** |
| 安庆 | 274 | **0** |
| 六安 | 5 | **0** |

**根因**：招标文件没下载到。
- 阜阳：附件页有 WAF（请求 `downloadztbattach` 返回 400「安全拦截信息」）
- 安庆：详情页是 390 字符壳（只有一段 `infourl.js` 引用）

解析逻辑已修（`attachments.ts` 放宽到任意标签 + `ztbfjyz`），但**下载被拦**。
不做反爬绕过。

**影响**：这五市在矩阵里能看「谁在赢」，但看不到「报多少」（下浮率全空）。

### 3. 「见招标文件」只有 2 条（预期 176）

大部分「详见前附表」和「业绩要求」不在同一句，或同句里有数字（触发实质门槛判定）。

**影响小**：这类项目在项目页显示「有实质门槛」而不是「见招标文件」，用户仍需翻原文。

## 三、已修的坑（别再踩）

| 坑 | 现象 | 修法 |
|---|---|---|
| `typeOfTitle` 只认「三级」 | 资质抽取 59%（政府文件写「叁级」） | 加 `[一二三壹贰叁]级` → 72.5% |
| 三态判定用拼接句 | 1,106 条业绩判反（人员业绩的「不要求」） | 只在命中句判 + 排除人员业绩 + 结论后置 |
| `cnt` 被「6个月」「2.10项目」污染 | 267 条 cnt≥5，大半是噪声 | `(?<![.\d])…(?!月\|标段)` + 遍历取最近 |
| 金额只认「不低于 1,000 万」 | 漏掉「1,000 万及以上」（更常见） | 两种写法都认 |
| 「自」字必填 | 「2021年1月1日以来」抽不到 | `(?:自\|从)?` |
| 矩阵按 segment 算、下钻按 type 过滤 | 矩阵写 127，点进去只有 50 | `market()` 加 `seg` / `city_other`（默认空） |

## 五、定时任务链路

```
crawl → attach → extract-docs → extract-deadline → extract-clauses
      → daily-digest（推送）→ agg-build（事实表）
```

`agg-build` 放在**日报之后**：它失败不影响推送；放前面会拖慢 06:00。
两个抽取器（deadline / clauses）都**不 gate 退出码** —— 抽取失败不连累日报。
