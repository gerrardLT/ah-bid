## 一、对照原始设想

用户最初的设想拆成六个环节：

> 爬取 2026 所有相关领域的招标文件和附件 → 用附件（招标书/CAD/工程量清单）生成技术标 → 把技术标按分类拆解建模 → 下次碰到相似招标先拆解要求 → 比对分析每一个细节项 → 微调编写施工组织设计

| # | 环节 | 状态 | 实际数字 |
|---|---|---|---|
| 1 | 抓取公告与附件 | ✅ 完成 | 22,272 公告 / 10,705 附件 / 26.96 GB |
| 2 | 解析招标文件（拆要求） | 🟡 **8.9%** | 1,982 / 22,272 |
| 3 | 生成技术标 | ❌ **0%** | 无任何生成能力 |
| 4 | 从技术标拆解建模 | ❌ 方向已改 | 0 份技术标可拆；改为规则驱动 |
| 5 | 相似项目匹配 | 🟡 部分 | 有清单匹配、评分项匹配；无"相似项目检索" |
| 6 | 比对细节项并微调 | 🟡 检查侧完整 | 缺口能定位到行，但给不了正文 |

**关键判断：环节 4 的原始设想（用 AI 生成的技术标建模）已被否决。**
理由是学到的是生成器的写法，不是评委的口味。替代方案是规则驱动 + 工程本体信号。

### 3.3 判定层：四层架构

```
规则（CSV）→ 文本（bid-text 切章）→ 判定（diagnose 三态）→ 交付（report/summary）
```

- 三态：`covered` / `mentioned`（有标题无证据）/ `missing`
- 六种证据：`term` / `number` / `section` / `cite` / `regex` / `volume`
- **两个防骗机制**：
  - `term` 命中后必须还剩 ≥8 字实质内容（防空小节标题）
  - `volume` 按**去重后**字数判定（防同一段重复灌水，实测抓出 313 字废话）

## 四、未实现

### 4.1 数据缺口（结构性，非代码问题）

| 缺口 | 数字 | 能否补 | 说明 |
|---|---|---|---|
| **招标文件解析** | 8.9% | ✅ 能 | 纯工作量，附件已下载 |
| **工程量清单** | 2.0% | ❌ 不能 | 站点不在附件里发造价成果文件，514 zip 只有 23 个含 Excel |
| 澄清 | 23.3% | 🟡 部分 | 站点只公示一段时间，过期不可得 |
| **技术标本体** | **0 份** | ❌ 只能你提供 | 平台不公开技术标正文 |
| **得分数据** | **0** | ❌ 不能 | 评标过程不公开，这是"建模"不可行的根因 |
| 图纸 | 241 dwg | 🟡 需装工具 | 环境无 ODA/dwgread/ezdxf |

### 4.2 能力缺口

| 缺口 | 现状 | 影响 |
|---|---|---|
| **生成能力** | 0% | 只能说"缺消防方案"，不能给方案正文 |
| 相似项目检索 | 只有标题模糊匹配 | 无法"找个类似项目参考" |
| 评分项→规则匹配精度 | 不看项目类型 | 供电工程的"服务方案"会匹配到服务类主题 |
| 面板跳招标文件 | 只跳标书原文 | 看不到"评分表里怎么要求的" |

### 4.3 验证缺口（最重要）

**所有准确率结论都建立在 4 份 fixture 上，而 fixture 是按规则机械生成的。**

- `eval 147/147` 证明的是"规则能被自己的测试集命中"，是循环论证
- `87.7% 覆盖率` 证明的是"规则要求 vs 清单要求"的匹配度，不是真实标书命中率
- **真实命中率未知，且一定会低于这两个数字**

## 五、离目标有多远

目标：**单项目命中率，靠针对性取胜**。

| 能力 | 完成度 | 备注 |
|---|---|---|
| 章节完整性检查 | **100%** | 不依赖项目数据 |
| 证据实质性检查 | **100%** | |
| 灌水检测 | **100%** | 去重字数 |
| 本项目考什么 | **96%** | 依赖评分表 |
| 规范引用核对 | **100%** | |
| 缺口怎么补（分段） | **100%** | 42 类方案模板 |
| 改稿进度追踪 | **100%** | 对比 + 历史 |
| 本项目有哪些活 | **2%** | 依赖清单，硬约束 |
| 本项目被质疑什么 | **23%** | 依赖澄清 |
| **帮你写出来** | **0%** | |
| **准确率被真实验证** | **0%** | |

**一句话结论：这是一个"检查器"的 90%，"生成器"的 0%，而入口覆盖率只有 8.9%。**

三个必须承认的事实：
1. 针对性最强的信号（清单硬约束）只覆盖 2% 的项目
2. 没有一份真实技术标，所有"能提升多少命中率"的说法都是推测
3. 生成能力为零——系统能定位缺口，不能填缺口
